About Me

Tallate

我是一名从 Java 后端和分布式系统出发，逐渐转向 AI Agent 工程的开发者。

这个博客记录的不是一条规划好的路线，而是一条不断追问“系统为什么这样工作、还能不能做得更可靠”的技术轨迹：从 JVM、并发、缓存、消息队列和搜索，到稳定性设计、Context Engineering、Memory、Multi-Agent 和 Harness。

经历

  • 东北大学 · 2014-09 — 2018-07
  • 用友 · 2018-07 — 2018-10
  • benmu · 2018-10 — 2021-02
  • 钉钉 · 2021-03 — 2024-08
  • 支付宝 Agent 开发 · 2024-09 — 至今

技术路径

后端与基础设施

Java、JVM、并发编程、MySQL、Redis、Elasticsearch、RocketMQ、Dubbo、Spring，以及缓存、搜索、限流、熔断、分布式事务和服务治理。

从系统到 Agent

最近更关注如何让 Agent 稳定地完成复杂任务：如何组织上下文，如何使用外部工具，如何管理短期与长期记忆，如何通过 Harness、子 Agent 和反馈循环提升可靠性。

我也在维护 self_modifying_bot，把同一个 Agent 接入微信公众号和网页，继续探索多渠道、可观测和可控的 Agent 系统。

开源项目

主要维护与个人项目

  • self_modifying_bot：微信公众号与网页入口背后的 Agent 服务，探索 Agent 的记忆、运行时切换、异步任务和可观测性。
  • ai_news_search：用于整理和搜索 AI 新闻的工具/技能项目。
  • hotkey：面向热点数据发现的实验性项目。
  • adaptive-loadbalance：自适应负载均衡相关实践。
  • docindex：抓取网页内容并建立索引。
  • PictureBed：个人图片保存工具。
  • tidp：幂等性校验相关实现。
  • tinycart：用于探索消息事务和电商流程的小型项目。
  • snake：基于 Linux 系统调用的联机贪吃蛇。

此外，GitHub 上还保留了一些参与学习、实验、镜像或 Fork 的公开仓库，例如 AWorld、OpenClaw、Apollo、Sentinel、RocketMQ、ZooKeeper 和 MySQL 等。它们体现了我关注和研究过的技术方向，但不等同于这些项目由我原创或独立维护。

我喜欢研究的问题

  • 一个抽象或中间件为什么要这样设计？
  • 系统在高并发、异常和故障下还能否保持可理解？
  • Agent 如何从“会聊天”变成“能把事情做完”？
  • 如何在自主性、记忆、工具能力和安全边界之间取得平衡？
