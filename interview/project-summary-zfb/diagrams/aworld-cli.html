三、上下文管理策略对比（AWorld vs 主流框架）

AWorld自研 AmniContext
  • 七种治理能力全覆盖
  • 树形 Task Context，子任务只传 result
  • 三级记忆 + 检查点断点恢复
  • Token 预算精细化控制
LangGraph
  • state + scratchpad
  • 图编排强，上下文靠自拼
  • 无内建记忆分层
Google ADK
  • InvocationContext 树形层级
  • 偏服务化接入
  • 压缩 / 卸载策略弱
Manus
  • Plan-Execute + 文件卸载
  • 产品体验好
  • 闭源，不可私有化

四、AWorld CLI 核心强项（一句话版）

短任务各家差不多，AWorld CLI 的护城河在「长程多 Agent 生产场景」：
底层用 AmniContext（七种治理 + 三级记忆 + 树形 Task Context）解决长程任务的上下文腐烂问题； 中层用 CAST（tree-sitter 三层索引，上下文压缩 70-90%）解决大代码库理解与编辑问题； 上层用 CLI + 多层级 Skill + 自定义 subagent 把 Harness 开箱即用化、可管道组合； 最后用 自进化闭环（Optimizer + Reward + 轨迹分析）实现 Agent 持续优化自身 Harness。
